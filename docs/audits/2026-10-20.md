# Full audit — 2026-10-20

Scope: upstream MACE changes, architecture, dependencies, security, code
quality, documentation, and app-screen finish (benchmarked against
[schrodinger.com](https://www.schrodinger.com)). Branch `v2.2` (= `main` +
`daily`), released as **v2.2.0**. Every finding below was verified by
execution unless marked otherwise; "fixed" names the commit.

`29659b4` CI · docs and UI commits follow on the same branch.

## Upstream MACE and the science

Upstream state on 2026-10-20: mace-torch **0.3.16** (2026-05-10) is the latest
release; `develop` has 60 commits since, including the start of a **v1.0
rewrite with no code or checkpoint compatibility** (#1699, #1715), a Python
3.11 floor and torch ≥ 2.5 for the next 0.3.x (#1759), and a fix that restores
the process default dtype after it is changed (#1659). Upstream's `mace_mp()`
default has been **MACE-MPA-0** since v0.3.10. New families since then — OMAT-0,
MATPES, OMOL, MH-1 (six heads), POLAR-1 — are under the Academic Software
License (non-commercial). ASE is at 3.29; `ase.md.npt.NPT` is a deprecated
alias of `MelchionnaNPT` since 3.27.

## Documentation

Three overlapping user-doc sets (MkDocs, in-app, a 27 KB README) contradicted
each other and the code: validator bounds (three different MACE-OFF ranges),
five version strings, dtype "requirements", `md` vs `molecular-dynamics`, a
removed `/generate-surface` endpoint, pressure in bar (the code uses GPa),
"coupled-cluster" for MACE-OFF, "DFT/quantum-accurate" on ~12 surfaces, an
"Academic" licence badge on an MIT project, and "5 categories" for a 4-category
catalog. There were no ADRs; 165 KB of process notes were published. Resolved
by ADR-0028 (one source per audience) and 30 ADRs.
